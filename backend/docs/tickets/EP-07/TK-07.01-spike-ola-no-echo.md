- O `AlexaController` legado já responde às consultas com dados reais, identificando o massoterapeuta pelo `ALEXA_USER_MAP`. Este spike usa isso para o primeiro teste com dados, sem mudar o código de produção.

## O que entregar

- Skill custom em pt-BR, com o nome de invocação "pausa", criada na conta de desenvolvedor da Amazon. O modelo mínimo é criado à mão no console; o versionado vem no TK-07.04.
- Backend local exposto por túnel HTTPS na porta 443, com o endpoint da skill apontando para `POST /api/alexa`.
- O Echo da demonstração cadastrado na conta de desenvolvedor ou como testador beta (L7).
- "Alexa, abrir pausa" respondendo com uma saudação, ouvida no Echo.
- Fase 2 do roteiro: com o seed de demonstração e o `ALEXA_USER_MAP` apontando para o massoterapeuta do seed, as três consultas respondem com dados do banco.
- Resultado registrado no `docs/alexa/roadmap.md` (Fases 1 e 2): o que funcionou, a ferramenta de túnel usada, o tempo de resposta observado e se "pausa" disputa com o comando nativo de pausar mídia (L9), testando "Alexa, abrir pausa" e "Alexa, pergunte à pausa…".
- Nenhum código de produção novo. Ajustes mínimos no legado só se forem indispensáveis para o "olá", registrados no roteiro.

## Critérios de aceite

- [x] **Dado** o backend local exposto pelo túnel, **quando** alguém diz "Alexa, abrir pausa" no Echo, **então** ouve a saudação.
- [x] **Dado** o seed de demonstração com atendimentos hoje e o `ALEXA_USER_MAP` preenchido, **quando** alguém pergunta pelo próximo atendimento, pela agenda de hoje e por quem chegou, **então** ouve os dados do banco, sem IDs.
- [x] **Dado** o comando "Alexa, pergunte à pausa quem é o próximo", **quando** é dito no Echo, **então** o resultado (funcionou ou foi tomado como "pausar") fica registrado no roteiro.
- [x] Fases 1 e 2 do `docs/alexa/roadmap.md` com status e observações atualizados.
