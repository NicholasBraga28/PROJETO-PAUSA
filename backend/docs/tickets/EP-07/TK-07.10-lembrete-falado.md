## O que entregar

- **Schema:** tabela `alexa_reminders` (`AlexaReminder`) com `appointmentId`, `alexaDeviceId`, `alexaReminderId` (da Amazon), `status` (criado, falhou, apagado, falha ao apagar) e datas; restrição única em (`appointmentId`, `alexaDeviceId`).
- **Parâmetro de negócio** `alexaReminderLeadMinutes` (RN-15, valor inicial 5 [VALIDAR]), editável pelo RH pelo fluxo do TK-03.07.
- **`AlexaReminderClient`**, token `ALEXA_REMINDER_CLIENT`: criar com o token da conversa e apagar com token LWA. Adapter real e dublê em memória, como o `NotificationChannel`. Só o `alexa/` o usa.
- **Criação durante a conversa:** em toda requisição com massoterapeuta identificado, o `AlexaReminderSync` compara as sessões restantes de hoje (`CONFIRMED`, não começadas, início depois de agora + antecedência) com os lembretes registrados para aquele aparelho e massoterapeuta e cria os que faltam. Idempotente.
- **Sem bloquear a resposta (RNF-02):** a sincronização roda depois que a resposta de voz é montada. Falha não é falada; a próxima conversa tenta de novo.
- **Remoção fora da conversa:** listeners (Observer) nos eventos de cancelamento, liberação e ausência apagam o lembrete com token LWA. Falha ao apagar é registrada e tentada de novo na próxima conversa.
- **Sem permissão (L2):** a conversa segue normal e o lembrete fica registrado como falho, para o RH ver.
- **Texto:** "Sua próxima sessão começa em {n} minutos.", sem o nome do colaborador (D-16), pelo catálogo.
- Credenciais LWA (client ID e secret) como variáveis de ambiente, obrigatórias só com o lembrete ligado, documentadas no `.env.example`.

## Critérios de aceite

- [ ] **Dado** três sessões `CONFIRMED` restantes hoje, **quando** o massoterapeuta abre a skill, **então** o dublê recebe três criações com o texto sem nome do colaborador, no horário início − antecedência.
- [ ] **Dado** os lembretes já criados, **quando** ele fala com a Alexa de novo, **então** nenhum lembrete é duplicado.
- [ ] **Dado** uma sessão que começa antes de agora + antecedência, **quando** sincroniza, **então** não cria lembrete para ela.
- [ ] **Dado** um lembrete criado, **quando** a sessão é cancelada, liberada ou marcada como ausência pela API, **então** o dublê recebe a remoção sem nenhuma conversa.
- [ ] **Dado** o dublê recusando por falta de permissão, **quando** o massoterapeuta consulta a agenda, **então** a fala é a mesma de sempre e o lembrete fica registrado como falho.
- [ ] **Dado** o dublê demorando, **quando** a consulta é feita, **então** a resposta de voz não espera a sincronização.
- [ ] **Dado** uma falha ao apagar, **quando** acontece a próxima conversa, **então** a remoção é tentada de novo.
- [ ] **Dado** o RH mudando `alexaReminderLeadMinutes`, **quando** a próxima sincronização roda, **então** usa o valor novo sem deploy.
- [ ] **Dado** o Echo de teste com a permissão concedida, **quando** o massoterapeuta abre a skill, **então** o lembrete toca antes da sessão; **quando** a sessão é cancelada, **então** não toca (Fase 8 do `docs/alexa/roadmap.md`).
- [ ] `npm run test`, `npm run test:e2e`, `npm run lint` e `npm run build` passam.
