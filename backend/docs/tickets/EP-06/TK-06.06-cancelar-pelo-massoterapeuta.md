## Contexto

- Spec: [EP-06, seções "Ações" (item "Cancelar") e "Eventos de domínio"](../../specs/EP-06-api-do-massoterapeuta.md#ações-tk-0603-tk-0606-e-tk-0607).
- Saiu do TK-06.03 na divisão de 2026-10-23.
- **D-05 (2026-10-22):** a antecedência mínima (RN-01) não vale para o massoterapeuta; o colaborador é avisado.
- **Decisão de 2026-10-23:** o cancelamento pelo massoterapeuta não oferece a vaga à lista de espera, porque ninguém vai atender naquele horário.
- Problemas do legado: o cancelamento do massoterapeuta passa pela RN-01, o evento leva o ID de quem cancelou no lugar do colaborador, o colaborador não é avisado e a vaga vai para a lista de espera.
- O texto da pergunta já vem na agenda (`confirmationText` de `CANCEL`, TK-06.02); quem pergunta é o cliente.

## O que entregar

- `POST /therapists/me/appointments/:id/cancel`, só `THERAPIST`:
  - sem a RN-01; o cancelamento pelo colaborador continua igual;
  - estados aceitos pela tabela de transições (`BOOKED`, `CONFIRMED`), com `updateMany` condicionado;
  - atendimento de outro massoterapeuta, `404` igual ao de inexistente;
  - resposta "Cancelado.".
- Payload do evento de cancelamento corrigido para `{ appointmentId, employeeId, cancelledById, cancelledByRole }`, com `employeeId` sempre o colaborador do atendimento. Os listeners de auditoria e da lista de espera passam a usar os campos novos; os cancelamentos pelo colaborador e pelo RH emitem o payload novo.
- O listener da lista de espera ignora o cancelamento quando `cancelledByRole` é `THERAPIST`.
- `NotificationKind` `APPOINTMENT_CANCELLED_BY_THERAPIST` (migração do enum) e aviso ao colaborador pelo `NotificationChannel` com a MSG-07: "Seu atendimento de {data}, às {hora}, com {primeiro_nome}, foi cancelado pelo massoterapeuta. Você pode reservar outro horário na página inicial."
- Cancela os avisos pendentes daquele atendimento, como hoje.
- Sai a rota legada de cancelar; a matriz de permissões troca a linha; o controller legado da Alexa passa a chamar o service novo.

## Critérios de aceite

- [x] **Dado** um atendimento `CONFIRMED` que começa daqui a 10 minutos, **quando** o massoterapeuta cancela, **então** vai para `CANCELLED` e responde "Cancelado." (D-05).
- [x] **Dado** o mesmo caso feito pelo colaborador, **quando** cancela, **então** a RN-01 continua recusando.
- [x] **Dado** o cancelamento pelo massoterapeuta, **quando** se consulta os avisos, **então** o colaborador recebe um aviso `APPOINTMENT_CANCELLED_BY_THERAPIST` com a MSG-07, só com o primeiro nome do massoterapeuta.
- [x] **Dado** alguém na lista de espera daquele horário, **quando** o massoterapeuta cancela, **então** nenhuma oferta é criada.
- [x] **Dado** alguém na lista de espera, **quando** o colaborador ou o RH cancela, **então** a oferta continua sendo criada (RN-10).
- [x] **Dado** qualquer cancelamento, **quando** se consulta a auditoria, **então** o colaborador é o do atendimento e quem cancelou aparece como ator, com o papel.
- [x] **Dado** um atendimento em estado que não aceita cancelamento, **quando** cancela, **então** recebe `409` com frase e nada muda.
- [x] **Dado** um atendimento de outro massoterapeuta, **quando** cancela, **então** recebe `404` igual ao de inexistente.
- [x] **Dado** o colaborador e o massoterapeuta cancelando ao mesmo tempo, **quando** processados, **então** só um vence e o outro recebe `409` com frase.
- [x] **Dado** `HR`, `ADMIN` ou `EMPLOYEE`, **quando** chama a rota, **então** recebe `403`; a rota legada não existe mais.
- [x] `npm run test`, `npm run test:e2e`, `npm run lint` e `npm run build` passam.
