## O que entregar

Com consulta periódica, o `GET /notifications` existente serve como feed do massoterapeuta, acrescido de:

- filtro "desde", para buscar só o que é novo;
- ordem cronológica;
- `spokenText` de cada aviso, pronto para `aria-live`, saído do formatador (TK-06.01) e do catálogo;
- marcação como lido.

## Critérios de aceite

- [x] **Dado** avisos antes e depois de um instante, **quando** o massoterapeuta consulta com "desde", **então** recebe só os posteriores, em ordem cronológica.
- [x] **Dado** cada aviso, **quando** lido, **então** traz `spokenText` de no máximo duas frases, só com o primeiro nome do colaborador.
- [x] **Dado** um aviso marcado como lido, **quando** consulta de novo, **então** ele vem marcado e a tela pode não lê-lo de novo.
- [x] **Dado** avisos de outro usuário, **quando** consulta, **então** eles não aparecem.
- [x] `npm run test`, `npm run test:e2e`, `npm run lint` e `npm run build` passam.

## Entregue

- `GET /notifications?since=<ISO>`: só avisos com `scheduledFor` posterior ao instante, em ordem cronológica, com `readAt`. O instante precisa de data, hora e fuso (`Z` ou `-03:00`); sem isso, `400` com frase do catálogo.
- `POST /notifications/:id/read`: grava `readAt` pelo `Clock` (idempotente, mantém o primeiro) e responde "Aviso marcado como lido."; aviso de outro usuário ou inexistente responde `404` "Aviso não encontrado.".
- Avisos de chegada e de possível ausência passam a dizer o horário pelo formatador (`atTimeOf`), corrigindo "14h:30" para "às 14h30".
- Migração `notification_read_at` (coluna `notifications.read_at`).

## Pendências encontradas na revisão

- O contexto supunha que o cancelamento pelo colaborador já gerava aviso ao massoterapeuta; não gera (não há `NotificationKind` para isso). Fica para um ticket próprio.
- O "desde" compara com `scheduledFor`, que nos avisos do massoterapeuta é o instante do evento. Um aviso gravado depois com `scheduledFor` igual ou anterior ao último lido não aparece; para não perder nada, a tela pode pedir um "desde" um pouco anterior ao último recebido e descartar os IDs já vistos.
- O `spokenText` do resumo ("Você tem N avisos.") conta lidos e não lidos.
