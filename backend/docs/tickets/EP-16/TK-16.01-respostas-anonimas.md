# TK-16.01 — Receber respostas anônimas

Status: ✅  
Épico: EP-16 · Spec: `docs/specs/EP-16-pesquisa-de-satisfacao.md`  
Depende de: —  
Tamanho: M  
Requisitos: RF-34, RN-18

## Contexto

Criar o armazenamento e `POST /feedback` para as cinco perguntas aprovadas. A resposta não se relaciona a colaborador, sessão, terapeuta ou unidade; envios repetidos são permitidos.

## Critérios de aceite

- **Dado** um usuário EMPLOYEE identificado e um payload válido, **Quando** envia `POST /feedback`, **Então** a API persiste somente notas, comentário opcional e ID aleatório, sem identidade, sessão, unidade, IP, user-agent, timestamp ou evento de auditoria.
- **Dado** Q1–Q4, **Quando** valida as notas, **Então** aplica os intervalos Q1 `1..5`, Q2 `1..4`, Q3 `1..5` e Q4 `0..10`, mantendo a ordem do template.
- **Dado** `comment` ausente ou vazio, **Quando** envia, **Então** aceita; comentário preenchido é texto simples limitado a 1000 caracteres.
- **Dado** nota inválida, campo extra ou comentário acima do limite, **Quando** envia, **Então** responde 400 e não grava dados.
- **Dado** mesmo payload enviado duas vezes, **Quando** processa ambos, **Então** cria duas respostas sem deduplicação.
- **Dado** falha no banco ou payload recebido, **Quando** a API responde, **Então** nenhum conteúdo de comentário nem dado de identidade aparece em logs.

## Testes esperados

- Unitários de validação, escalas, comentário vazio/longo, duplicidade e persistência sem colunas de relação.
- E2E de papel EMPLOYEE, acesso negado para outros papéis, envio válido, campos extras, escala fora do limite e dois envios iguais.
- Verificação da migração e do schema sem FKs para Employee/Appointment.
