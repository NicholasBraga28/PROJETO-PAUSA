# TK-09.03 — Cliente da API tipado e validado

Status: ✅
Épico: EP-09 · Spec: docs/specs/EP-09-base-do-frontend.md
Depende de: TK-09.02
Tamanho: M
Requisitos: RNF-04

## Contexto

O `api.js` devolve o JSON do backend sem verificar o formato, e a identificação do protótipo (`x-user-id`) é passada em toda chamada pelos componentes. O cliente passa a ser o único ponto de contato com o backend: tipa os contratos, valida as respostas e isola a identificação para o login Google entrar sem espalhar mudanças.

## Critérios de aceite

- **Dado** uma resposta válida, **quando** a tela a recebe, **então** o dado passou pelo esquema Zod do contrato (D-22) e tem o tipo inferido dele (`z.infer`).
- **Dado** uma resposta fora do contrato, **quando** o cliente valida, **então** lança `ApiError` com a mensagem genérica, a tela anuncia o erro com `role="alert"` e nenhum dado parcial aparece.
- **Dado** um erro 4xx com mensagem do catálogo, **quando** a tela mostra o erro, **então** aparece o texto do backend, nunca o corpo bruto ou o código HTTP sozinho.
- **Dado** o código-fonte, **quando** procuro `x-user-id` ou a chave `userId` do `localStorage`, **então** só aparecem em `features/auth` e `shared/api`.
- **Dado** um parâmetro de caminho (ID, token), **quando** vai para a URL, **então** passa por `encodeURIComponent`.
- **Acessibilidade:** toda mensagem de erro do cliente é uma frase em português que diz o que aconteceu e o que fazer.

## Arquivos prováveis

- `shared/api/client.ts`, `shared/api/api-error.ts`, `shared/api/schemas.ts`
- `package.json`: `zod`
- `features/*/api.ts`
- `features/auth/session-storage.ts`
- `features/booking/session-duration.ts` (descoberta da duração)

## Testes esperados

- Cliente: sucesso, 204, erro com mensagem, erro com array de mensagens, sem rede, resposta fora do contrato.
- Descoberta da duração: começa pela salva, pula as recusadas, guarda a aceita, falha com mensagem clara.
