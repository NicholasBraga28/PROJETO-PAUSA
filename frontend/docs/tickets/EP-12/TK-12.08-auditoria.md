- API: `GET /audit-events` com filtros e cursor.

Consulta read-only dos eventos de `Appointment`. O backend limita campos, ordena por `createdAt DESC`/`id DESC`, retorna `nextCursor` e omite dados pessoais/payloads não permitidos.

## Critérios de aceite

- **Dado** filtros opcionais de período, agendamento, ator ou ação, **Quando** o RH consulta `/hr/audit`, **Então** envia os filtros a `GET /audit-events` e lista somente eventos de `Appointment` na ordem mais recente primeiro.
- **Dado** mais resultados que o limite da página, **Quando** o RH escolhe “Carregar mais”, **Então** usa `nextCursor`, mantém os filtros e evita duplicar ou pular itens.
- **Dado** um evento, **Quando** apresentado em tabela/lista, **Então** comunica ação e data/hora, autor (“sistema” quando `actorId` é `null`) e campos de auditoria permitidos; não exibe nem anuncia e-mail, dado de saúde, payload arbitrário ou ID completo como texto de leitura.
- **Dado** consulta sem resultados ou cursor inválido, **Quando** a API responde, **Então** anuncia o estado vazio ou erro do catálogo; cursor inválido oferece reiniciar a consulta desde o início.
- **Dado** filtros, **Quando** são apresentados a teclado/leitor de tela, **Então** têm rótulos visíveis, foco previsível, associação de erros e nomes acessíveis que incluem o texto visível.
- **Dado** resultados de auditoria, **Quando** são lidos ou apresentados a 320 px, **Então** a coleção usa `<caption>`, cabeçalhos `<th scope="col">`, ordenação anunciada e versão em lista responsiva sem rolagem horizontal; cada linha usa `spokenText` curto quando fornecido.
- **Dado** um evento de sistema, **Quando** é apresentado, **Então** `actorId: null` é anunciado como “Sistema”; ações/códigos futuros recebem fallback compreensível sem revelar identificadores completos.
- **Dado** qualquer tema, preferência de contraste ou zoom, **Quando** a tela é usada, **Então** mantém contraste de texto 7:1 (4,5:1 para texto grande), componentes/foco 3:1, suporte a `forced-colors` e reflow a 400%/320 px sem rolagem horizontal.
- **Dado** sucesso ou erro, **Quando** o estado muda, **Então** a região viva anuncia o `spokenText` da API literalmente; erro impeditivo usa `role="alert"` e anúncio de carregamento/página ocorre uma vez sem deslocar foco.
- **Dado** a entrega da tela, **Quando** testes automáticos e roteiro manual são executados, **Então** axe, foco, teclado, nomes acessíveis e anúncios passam; validar NVDA + Chrome/Firefox, 400%, alto contraste/`forced-colors`, daltonismo e movimento reduzido.

## Comentários

- RF-22 permanece com prioridade `[M/S/C/W]` não definida em D-14; o roadmap mantém este ticket no escopo do EP-12.
- Auditoria é somente leitura. Não adicionar ações de editar/excluir eventos nem enviar dados a analytics.
- O endpoint retorna `actorId`, mas não o nome do autor. A interface identifica eventos com `actorId: null` como “Sistema” e os demais como “Usuário identificado”, sem apresentar IDs completos.
- Validação executada: `npm run typecheck`, `npm run lint`, `npm run test` (45 arquivos, 249 testes), `npm run build`, `npm run check:contrast` (38 pares em 7 temas) e Playwright de acessibilidade da auditoria (18 cenários: axe, Tab, 320 px/400%, cores forçadas e movimento reduzido nos temas).
- Roteiro manual pendente: validar com NVDA + Chrome/Firefox e simulador de daltonismo. Os testes de teclado/contraste/reflow/cores forçadas foram executados com Playwright e script automatizado.
